# pin

Cross-platform (macOS, Linux, Windows) clipboard manager in Rust: encrypted history, search, pins with hotkeys, secrets vault. Desktop UI on egui/eframe plus a CLI.

## Workspace

- `crates/pin-core` — owns all domain state: entries, storage, crypto, search, pins, secrets. No UI or platform clipboard code here.
- `crates/pin-app` — egui/eframe desktop app; only renders state and forwards user actions to pin-core.
- `crates/pin-cli` — binary `pin`; thin layer over pin-core.
- `crates/pin-clipboard` — platform clipboard watching and writing, per-OS modules behind `cfg(target_os)` (`macos`; other targets return `Error::Unsupported` until implemented).
- A new feature gets its own module; `lib.rs`/`main.rs` only wire modules together.

## Commands

```sh
cargo build --workspace
cargo test --workspace
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo run -p pin-app
cargo run -p pin-cli
```

Before finishing a change: fmt, clippy with `-D warnings`, tests must pass.

## Design decisions

- Content types: everything the OS clipboard carries — plain text, rich text/HTML, images, file lists. Store all representations of one copy event as one entry with several formats.
- Storage: SQLCipher (rusqlite `bundled-sqlcipher`; CommonCrypto on macOS, vendored OpenSSL elsewhere), raw 32-byte key, WAL, `secure_delete = ON`, `temp_store = MEMORY`. Plaintext never touches disk (no temp files, no unencrypted caches or thumbnails). Write paths use IMMEDIATE transactions because pin-app and pin-cli share the database.
- Search: FTS5 trigram over plain text or decoded file paths (first 64 KiB) for queries of 3+ chars; 1–2 char queries scan previews with Unicode case folding.
- Pins: `Entry.pin` is `Pin::{None, Pinned, Slot(PinSlot)}`.
- Ordering: pinned first, then `use_seq` (monotonic counter bumped on copy/paste), not wall-clock time.
- Key: random data key generated on first run, stored in the OS keychain via `keyring-core` with one store per OS (macOS Keychain, Windows Credential Manager, Secret Service over synchronous libdbus on Linux — no zbus/async runtime). Apps open the database with `Store::open_with_keys(path, &Keychain, ..)`: a `pin.db.lock` file lock serialises first runs, and a missing key next to an existing database is an error, never a silent new key.
- Secrets: vault tables in the same database. A random vault key is wrapped twice: by an Argon2id key from the master password and by a recovery key shown once at vault creation and replaced after each use. The vault is reached through `store.vault()` (`crates/pin-core/src/vault/`); its key never leaves `vault::Session`. Secret name, note and every format are sealed separately with XChaCha20-Poly1305 under the vault key; AAD binds the vault uid and secret uid. The database key alone does not reveal secrets. The vault auto-locks after 5 minutes idle (`Options::vault.auto_lock`); a key from a vault reset by another process is dropped on next use. Secrets are never put into the search index, history list, logs or the CLI output unless explicitly unlocked. Zeroize key material and decrypted secrets after use.
- Pins: pinned entries are exempt from history limits and sorted on top; a pin can have a paste hotkey.
- Dedup: identical content (by hash) bumps the existing entry instead of inserting a new one.
- Clipboard capture: `pin_clipboard::watch` polls on its own thread (macOS: `changeCount` every 500 ms) and hands each copy to a callback as a `NewEntry`. Only the first item's text/HTML/RTF/PNG and file URLs from all items are stored; TIFF-only images are converted to PNG. Copies marked `org.nspasteboard.ConcealedType`/`TransientType`/`AutoGeneratedType` and copies over 100 MB are skipped. Secrets are written back with `Privacy::Concealed` so pin and other managers don't capture them; the app passes the `ChangeCount` of its own writes to `WatchHandle::ignore` so they are not re-captured.
- Database location: `pin_core::default_database_path()` (OS data dir, `pin.db`), shared by pin-app and pin-cli; default history limit 200.
- App window: a popup toggled by the global hotkey Cmd+Shift+C (Ctrl+Shift+C elsewhere); Cmd+Ctrl+1..9 (Ctrl+Alt+1..9) copy a pinned slot without opening it. Choosing an entry only copies it (no auto-paste) and hides the window; Esc, focus loss and the close button hide it, Quit exits. On macOS pin is an Accessory app (no Dock icon) and `NSApp.hide` returns focus to the previous app; if the open hotkey can't be registered it falls back to a Dock icon so the window can always be reopened.

## Performance budget

pin runs all the time, so idle cost matters more than peak speed.

- Idle CPU ~0%: event-driven clipboard watching where the OS supports it (Windows `AddClipboardFormatListener`, Wayland data-control, X11 XFixes); on macOS poll only `NSPasteboard.changeCount` (cheap integer) at a low interval.
- The UI window is created on hotkey and does not repaint when hidden; no continuous repaint.
- Load large payloads (images, files) lazily; the list shows previews/thumbnails, full data is decrypted only on use.
- Search must stay interactive on 10k+ entries; avoid decrypting the whole history per keystroke.
- Release profile: thin LTO, `codegen-units = 1`, stripped.

## Git

- No Linear for this repo: do not use Linear tools; branch names are `type/short-name` without a task key.

## Code rules

- Rust 2024 edition, stable toolchain, workspace lints apply to every crate (`[lints] workspace = true`).
- No `unwrap`/`expect` outside tests; errors via `thiserror` in libraries, `anyhow` only in binaries.
- No comments except a short WHY for a non-obvious constraint or workaround.
- Shared dependency versions go in `[workspace.dependencies]`.
- Never log clipboard contents or secrets, even at debug level. pin-core logs via `tracing` only ids, counts and error kinds; binaries install a stderr subscriber with level from `PIN_LOG` (default warn). Types holding content or key material get a hand-written `Debug` that omits it.
- `#![forbid(unsafe_code)]` in every crate except `pin-clipboard`, which needs FFI: there every `unsafe` block is minimal and has a `// SAFETY:` comment (`clippy::undocumented_unsafe_blocks` is denied). Use `#[expect]`, not `#[allow]`.
- macOS pasteboard tests need the pasteboard server, which the Claude Code sandbox blocks; run `cargo test -p pin-clipboard` outside it. Tests use private unique pasteboards, never the general one.
